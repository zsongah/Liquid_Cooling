5. 控制与在线校准

当前是有界规则控制，先计算液冷热需求，再调流量或压差。没有深度学习控制器，也没有以总冷却能耗为目标的优化求解。

text
热负荷 Q = 独立液冷热负荷（若有）
         或 cp × 实测质量流量 × (回液温度 − 供液温度)
需求热量 = max(当前热负荷, 有效外部预测峰值)
可用温差 = min(目标温差, 回温软限值 − 当前供温)
需求流量 = 需求热量 / (cp × 可用温差) + 正温差超差反馈

流量模式：目标 = 有界需求流量
压差模式：稳态压差 = (有界需求流量 / gain)^(1/exponent)
          候选 = 稳态压差 + dp_feedback_gain × (稳态压差 − 实测压差)
再经设备范围、单次幅度、死区、最短间隔和命令网关检查

无效数据、告警、供温超过策略回温软限值等条件会阻止正常优化。需求超能力记录容量不足，不能通过不断增大目标保证超出设备容量的需求。

一阶回温预测使用配置 thermal_tau_s 与 horizon_s。如果负荷来自同一组当前温差/流量且无独立预测，可能退化为持值预测；低误差不能证明预测有效。

5.0 水力模型与实际压差反馈（v0.4.1）

默认通用配置保持旧控制行为；当前 FMU 示例已切换为修正模型。三个 gain 不要混淆：水力 gain 将压差换算成流量；dp_feedback_gain 是新增外环 P 反馈；FMU 本地 PID 的 k 是设备内部参数，本次未修改。

参数含义与取值
hydraulic_model显式给出 exponent、gain、gain_bounds 三个字段；不能与旧 flow_per_sqrt_kpa / 顶层 gain_bounds 混用
exponent0.25–1.5 内的固定模型指数；旧模型 0.5；本次 FMU 1.0，不能直接套给其他 CDU
gain单位 kg/s/kPa^exponent；FMU 固定负荷 hold 辨识为 0.0646448823，边界 [0.04, 0.09]
dp_feedback_gain0–2，无量纲，默认 0；只用于压差控制；FMU 取 2。逐步逼近后补偿消退，无积分积累，仍经过限幅限速
calibration_max_dp_error_kpa可选正数；当前压差未靠近回读目标时清空训练窗口并冻结晋升；FMU 取 0.5 kPa

反馈默认关闭，现场须按实际阶跃结果整定。反馈可能增加瞬态泵耗，不能由“误差下降”直接推出节能。FMU 示例的指数和初值只来自先前恒定负荷数据，不读取评估时段的未来负荷。修正实验没有触发在线晋升，效果来自事前辨识与反馈。

新增决策记录 equilibrium_control_target（模型稳态目标）、raw_control_target（含反馈候选）、bounded_control_target（限幅）、limited_control_target（限速）、flow_tracking_error_kg_s、dp_tracking_error_kpa、model_flow_at_min_dp_kg_s / model_flow_at_max_dp_kg_s。实际执行仍以 receipt 与 Master 写入日志为准。记录 control_rate_limited、control_below_minimum、feedback_command_clipped 等原因，保留原需求曲线，不通过改需求假装跟上。

当前上限由 policy.py 的 DP_FEEDBACK_GAIN_BOUNDS = (0.0, 2.0) 明确限制。2.0 是软件允许整定范围的上界，不是设备物理上限，也不是所有机房的稳定性保证。已有 FMU 矩阵只测试 0、1、2 三个离散值；小幅负荷下 Kp 从 0 增到 2，流量 MAE 由 0.508 增至 0.600 kg/s，泵耗由 3.511 增至 3.633 kWh。增大 gain 不保证更准确或更节能。扩大支持范围前，应补充延迟、噪声、限幅限速和多负荷工况验证；当前不会因单次配置值合法就推荐用于现场。

5.1 学习逻辑与参数恢复

只校准 flow ≈ gain × dp^exponent 中的聚合增益，exponent 固定、不在线学习。旧配置仍为平方根模型（exponent=0.5）；参考 FMU 修正配置采用局部辨识的线性模型（exponent=1）。需要正常质量、无告警、准稳态、非执行器边界且有足够压差变化。缺实际压差、异常或明显瞬态时冻结/清理样本，不把目标当测量拟合。

最近最多保存 60 个合格样本，最后 8 个按时间保留验证，训练至少 12 个；至少积累 20 个后，按采样计数每 10 个尝试候选。候选在 gain_bounds 内、单次变化最多 ±2%、验证 MSE 改善超过 2% 才可晋升；adaptive_enabled=false 时仅记录候选。

现场先关闭自动晋升，积累数据再开放。滚动保留窗口可重叠，不替代独立长期验证。学习不会放宽 guards 或 controls。原始数据和晋升写入 SQLite；相同完整配置可恢复已发布参数，重启后拟合窗口重新积累。

更准确不自动等于更省电或更快。 直接流量模式不使用该增益换算目标；本轮 FMU 校准后泵电量增加。响应速度、温度和能耗应分别评价。

7.1 适配包和联调顺序

适配包对应厂家、型号、控制器/固件和通信文档版本。只变地址、编码、单位和限值可改配置；协议、握手、回退语义变化需要扩展适配器并测试。

  1. 确认对象是 CDU、群控 PLC 还是平台，明确目标属主；避免与 iCooling/BMS 同时写同一目标。
  2. 从 examples/field_template.UNBOUND.json 绑定真实点表、权限和限值，删除不能证实的可选点；保持 write_enabled=false、adaptive_enabled=false。
  3. validate 后 monitor，逐点对照设备面板，核对量程、单位、功率边界、告警、模式、属主和源刷新。
  4. 实测目标写入/回读/过程响应、手动优先、唯一控制权、本地接管、断网、进程退出和设备重启。
  5. 保存 commissioning 证据，再 shadow 与小范围 control；当前 shadow 也检查真实可控模式/归属，只读本地模式使用 monitor。
  6. 建立温度、动作、能耗基线，再逐步开放校准；一个型号联通不代表全品牌兼容。

供温写入还需 OEM 防凝露保护证据，或有效露点观测与余量。当前自动算法不调温，通用网关仍检查温度请求。缺少机柜关键温度/流量时，不能推断机柜热安全。

首次使用建议按以下流程操作，无需硬件：

  1. 从配置列表选择 workbench_physical 模板。该模板含一个 CDU、两个机柜及四个节点，声明供回端口连接，所有数值均为合成试验条件。
  2. 查看拓扑并选中 CDU。没有运行数据时显示未采集；机柜和节点只有资产关系，没有凭空生成分支温度或流量。
  3. 在配置工作台点击“复制为新草稿”，然后修改名称、算法参数或连接字段，必要时通过高级 JSON 编辑资产、端口与连接。模板与已发布版本只读；画布拖动仅修改布局草稿。
  4. 执行配置检查，查看错误、警告与域能力。检查通过只证明当前软件的配置语义成立，不证明设备连通或现场安全。
  5. 保存草稿并发布。草稿可反复修改，revision 乐观锁防止旧页面覆盖新修改；发布版本冻结，后续修改应复制为新草稿。发布不会启动设备或改变已有会话。
  6. 在运行页选择发布版本、控制域、合成仿真、运行模式和时长。典型开发设置为 300 秒仿真时长、5 秒数值步长、20 倍运行速度；速度只压缩等待，不改变仿真步长。真正推进 ThermalPlant 并调用现有 Engine，不使用随机演示数据。
  7. 在“运行与验证”页查看实际温压流和功率，并对照需求与目标；在“控制追踪”页选择一个周期，检查原始建议、限幅、限速、回执和实际响应。结束后记录仍可回放。

高级 JSON 有未应用内容时，常用参数和资产表单会锁定；可以切换页面查看，但需先“应用 JSON 到草稿”或显式“放弃 JSON 修改”再继续编辑，避免两种编辑方式相互覆盖。放弃只恢复到当前本地草稿，不撤销先前已经应用的其他草稿修改。应用 JSON、保存草稿、发布版本是三个不同动作。

运行视图中，所选任务的 CDU 始终使用该任务的遥测和决策，即使缺测也不会借用较新任务的数值。拓扑内其他 CDU 可补充该配置各域的最新记录，详情标出任务、采样时间和历史状态；这些记录不构成同步的全站瞬时状态。

合成热对象仍是 CDU 聚合模型，不能因配置里有机柜节点就宣称完成逐柜热仿真。workbench_independent_cdus 展示多个独立控制域，可按域创建独立任务；不具备共享水路或共享冷源容量调度。实际 Sustain FMU 记录可在工作台中回放，新实验继续使用第 9 节专用 Master/Docker 入口；工作台未实现网页启动任意 FMU。

HTTP API 仅绑定回环地址，带 Host/同源检查、会话 Cookie、写操作 CSRF、请求体大小限制和固定文件路由。前端不能提交任意 shell 命令、任意文件路径或直接发设备报文。服务没有实现互联网发布、TLS、多人角色与审批系统；需要远程访问时，应由现场经过认证的安全访问通道连接回环服务。

8.4 功率预测：从输入接口到实际控制

“功率预测”是独立页面。没有上游数据时显示未接入；软件不会生成一条看似真实的曲线。选择已发布配置后，可查看该配置的资产、控制域和接入契约，粘贴 JSON 或选择本地 JSON 文件，先校验再提交。接口 descriptor 的 example 提供明确标为 synthetic 的试验模板；读取模板或校验输入不会启用前馈。提交后，匹配任务在下个决策周期读取，提交本身不启动任务。

输入字段要求与用途
forecast_id上游生成的唯一编号；相同编号不能覆盖不同内容，旧发行时间不能覆盖新预测
source.kind / source.name来源类型与名称；合成输入 synthetic，实际外部输入 external
clock_basissimulation 为每次运行起点 0 的相对秒；unix 为 Unix 秒，不能混用
issued_at / valid_from / valid_until发行时刻、有效区间；不得用未来发行时间，样本必须覆盖有效区间端点
max_age_s允许的原始预测年龄，上限 3600 秒；每周期重新检查，物化时间不能延长它
unit必须是 W_e，表示电功率；不能把 kW 数值直接填写，也不能用热功率冒充电功率
selectioncentral 使用 power_w；upper_bound 要求所有样本显式提供上界
entries[].asset_id当前配置中的机柜或节点 ID；节点必须归属于机柜，机柜唯一归属控制域
entries[].liquid_fraction0–1 的液冷捕热比例，须来自工程依据；不能默认全部 IT 电功率进入液路
entries[].samples严格递增且对齐的时间网格，每点含 at / power_w；可有 lower_power_w / upper_power_w
job_id（可选）更新正在运行的仿真时指定任务，用其相对时间校验；不是修改配置或发设备命令

同一机柜只能输入整柜预测，或输入全部已配置节点预测，不能将父机柜和子节点重复计入。节点全覆盖仍不证明未建模的机柜辅助负荷已被包含。当前每包最多 512 个资产、每资产 721 点、合计 50000 点，有效区间不超过 24 小时；HTTP 请求还受 2 MiB 上限约束。缺少某域的任意机柜，该域拒绝前馈并保留反馈，其他覆盖完整且互斥的域仍可使用。

  → 需求流量、流量/压差目标、原有限幅限速与安全网关
  → 实际仿真或 Modbus 设备，记录 forecast_usage 与 decision

聚合峰值是“同一时刻相加，再取峰值”，不能将各柜在不同时刻的峰值直接相加。内部桥接包为兼容原 FlowPolicy 使用液侧等效功率及比例 1；对外仍分别保留原始电功率和液侧热负荷，不改变原始预测。内部 materialized_at 是此次物化时刻，source_issued_at 始终保留原发行时间。预测不会修改 ThermalPlant 的实际负荷输入。

需求计算沿用 m_dot = Q_demand / (cp × ΔT_available) 和原有温差反馈，其中可用温差同时受目标温差及回液软限值约束。压差模式再通过当前水力模型换算成压差，最后经过限幅、限速和命令网关。预测可在负荷到来前提高总流量需求；当前没有自动估计输运延时、选择最优提前量或储冷模型，horizon_s 应依据对象的实测响应设置。

页面明确分开三种状态：聚合预览 ready、实际周期 used/not_used/rejected/absent，以及网关命令是否确认。used 只表示策略采用该预测，不证明冷量已经到位；查看同周期目标、回执、实际温压流与 forecast_id 才能追踪效果。过期、时钟不符、超出热负荷范围或覆盖不足会保留原因；撤回预测只让后续周期恢复反馈，不是停泵或撤销已经下发的目标。

原始输入先归档到工作台状态目录的 forecast_archive/<config_id>/<sha256>.json，成功后才激活。SHA-256 对应归档文件实际字节；当前记录、每周期 usage 和 decision 保留 input_sha256。同目录的 id_index.json 将编号与内容永久绑定，替换、清除及重启后也不能用同一编号提交不同内容。新预测替换或清除当前输入不会删除旧曲线。归档或索引失败、路径异常、已有归档损坏时拒绝激活；恢复持久化输入重新校验，不刷新原始发行时间。页面核对编号和内容哈希，旧无哈希记录明确标注核验边界。归档当前通过文件与审计记录追溯，尚无界面历史版本浏览器。

12. 数据、故障与恢复

SQLite 使用 WAL/FULL，事件含 session、telemetry、decision、calibration、model、fault、forecast_input_error、forecast_usage。commands.jsonl 保存模式、dispatch_intent、回执、交接。写意图先落盘同步，再发设备命令；采样存储失败不静默丢弃。

状态/原因含义与处理
setpoint_confirmed目标回读一致，继续观察实际响应
shadow未执行候选，不计算实际节能
control_owner_mismatch / device_mode_mismatch模式/归属不允许，核对交接，不伪改枚举
temperature_protection_not_verified缺所需防凝露证据/露点条件，维持温度写入禁用
minimum_interval_not_met动作太密，等下一周期，不删除保护
invalid_guard_observation / stale_source守护量/源刷新异常，检查采样链路
uncertain / restart_pending_intent结果未知，禁止自动重发，核对设备并保留审计
handoff_unconfirmed未确认本地接管，核对设备模式和看门狗
exit_code=2本次故障，查看 fault 和命令日志再决定恢复

同命令 ID 不重复写，冲突 ID 拒绝。未完成意图、不确定动作或损坏审计阻止重启自动控制。先核对设备目标/模式/接管，保存处置证据及原日志，确认交接后建新会话；不要删审计解锁。 没有自动对账/回滚向导，不应无条件重启为 control。

没有自动留存、备份、磁盘容量治理或高可用。长期边缘运行前需补齐；学习模型不替代设备保护。
